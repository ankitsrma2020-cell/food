# food reviewer notes

## Architecture

This is a split full-stack JavaScript application: an Express/Node backend under `backend/` and a Vite React frontend under `frontend/`. The root scripts orchestrate installation, concurrent development, frontend builds, and backend startup. Both applications use native ES modules via `"type": "module"`.

## Conventions

- Use ES module syntax throughout; `backend/package.json`, `frontend/package.json`, and `.vite-cache/deps/package.json` all declare `"type": "module"`.
- Keep backend and frontend dependencies isolated in their respective directories. Root `package.json` installs them with `npm install --prefix backend` and `npm install --prefix frontend`.
- Run the backend from `src/server.js`; both `backend/package.json` scripts (`dev` via nodemon and `start` via Node) target that file.
- Run the frontend through Vite. `frontend/package.json` defines `dev`, `build`, and `preview`, while `frontend/vite.config.js` enables the React plugin and fixes the dev server to port `5173`.
- Treat the root scripts as the supported integration points: `npm run dev` starts both services through `concurrently`, `npm run build` builds only the frontend, and `npm run start` starts only the backend.
- The frontend uses React with `react-router-dom` for routing and `lucide-react` for icons, as declared in `frontend/package.json`.
- `.vite-cache/` is a Vite dependency-cache directory configured via `cacheDir: '../.vite-cache'`; files there are generated dependency artifacts, not application source.

## Intentional non-standard choices

- Package names are inconsistent with the repository name: the backend is named `mosaic-api` and the frontend `mosaic-web`, while the root package is `mosaic-social` (`backend/package.json`, `frontend/package.json`, and root `package.json`). Do not flag this as an implementation defect without evidence that published package identity matters.
- The root project is private and is primarily an orchestration workspace; runtime dependencies belong in `backend/package.json` or `frontend/package.json`, not necessarily the root manifest.

## Watch out for

- Do not review or manually edit `.vite-cache/deps/*` as source code; changes there are likely generated by Vite and should generally be regenerated.
- Preserve the separate service boundaries and scripts. Changes to backend or frontend startup paths must also update the corresponding root scripts.
- Backend changes should account for the existing Express middleware/auth/upload stack (`cors`, `cookie-parser`, `jsonwebtoken`, `multer`, `cloudinary`, and `bcryptjs`) rather than introducing a conflicting runtime pattern.
